# 黄金CRM概念 MVP

React + TypeScript + Vite + Ant Design。只在本机运行，使用当前浏览器 localStorage；没有服务端、数据库、支付、真实小程序接口或外部大模型。

## 启动

安装 Node.js 后，在本目录执行 `npm ci`，再执行 `npm run dev`。打开 http://127.0.0.1:5173/。默认仅监听本机；端口被占用会报错。`npm run build` 进行类型检查并生成 `dist`；`npm test` 检查核心业务约束。

## 建议查看顺序

1. 工作台切换岗位，处理待办或跳到对应订单。
2. 客户与跟进创建客户、登记回访，会员身份在档案里维护。
3. 商品与设计确认方案；规格或费用变化用新版本，旧版保留。
4. 销售与订单新建、确认、调整报价。订单保存当时设计和报价版本。
5. 工厂与质检登记累计用料、费用和检验。失败进入返工，登记返工费后复检；合格订单可回销售登记交付。
6. 在销售登记收款，再到财务核验；两个模块显示同一记录。财务可登记退款及费用。
7. 采购与库存查看批次流水、回收量、损耗；采购入库和有原因的盘点差额会更新可用库存。
8. 营销中心创建活动并添加线索；线索进入统一客户库，活动统计关联客户的有效订单。
9. 售后与服务记录申请和处理结果，通过关联模块继续订单、工厂或财务处理。
10. 数据统计切换时间/渠道，导出明细并查看原始记录。AI看板从相同记录计算。
11. 行情中心暂停/更新模拟金银价格，切换趋势范围与情景估价。
12. 系统与集成模拟同步失败、重试、防重导入、进度回传；查询商品/库存JSON，查看请求和操作日志。AI助理可查询客户姓名或订单号并跳到依据。

## 数据口径

- 金额按整数分、重量按整数毫克保存；界面显示元和克。
- 收款、生产、交付独立。未核验资金不计入已收款，退款不能超过已核验收入；核验限模拟财务、经营负责人和管理员。
- 批次成本固定；实际成本＝批次价×实际净用料与已确认损耗＋设计快照附材/销售费＋已登记费用。设计中的加工费是计划值，实际费用须另登记。未完成订单成本可能不完整。
- 工厂用料表为同一订单/批次的累计总量，重新保存更新该记录。可用退料归原批次；回收料单独展示，未确认再利用前不计入可用库存。尚未归属重量在制作中记为在制，质检前须平衡；未知差额不得冒充已确认损耗。
- 行情与估价仅是模拟场景，AI为本地确定性查询；不覆盖历史业务记录。
- 刷新会恢复浏览器数据。保存失败不会假成功，表单输入保留。损坏的保存记录不自动覆盖，在系统中明确恢复初始演示数据。

## 文件职责

`src/domain.ts` 负责种子与业务约束；`src/store.tsx` 负责串行操作和保存；`BusinessPages`、`OperationsPages`、`InsightPages` 共用同一状态；`App.tsx` 负责导航和岗位；`styles.css` 负责共享视觉及响应式。

行业计价、负责人、审批权限、小程序字段映射尚未经过商家确认。本版本用于讨论流程，不能作为生产财务系统。
