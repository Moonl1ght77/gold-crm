## 3. 演示外壳

**演示控制栏**（固定在页面顶部，属于演示工具，不属于企微界面）：
- 身份：16 个岗位分 6 组下拉，模拟当前的企微登录人
- 视图：手机 / 桌面
- 形态：工作台 / 侧边栏 / 消息 / 客户联系
- 主题：深 / 浅
- 页面说明：开 / 关

身份、视图、主题存在本机浏览器，读写失败就退回默认值。

**手机视图**：桌面浏览器里居中显示 390×844 的手机框，内含企微式顶栏和底部 Tab。Tab 共四个：工作台、该岗位的两个主要模块、我的；例如门店顾问是"工作台 / 客户 / 业务单 / 我的"。"我的"里放应用宫格，列出当前岗位可见的全部模块。应用内不另设消息 Tab，提醒统一走"消息通知"形态，和真实企微一致。真机窄屏打开时，手机框铺满全屏，不显示边框。

**桌面视图**：模拟企微桌面端。左侧是模块侧栏，中间放大表格或看板，右侧是详情抽屉。视口窄于 1024px 时禁用桌面视图。

**页面说明**：每页一段简短说明，写清这页做什么、对应图稿哪个主题、哪些待商家核实。手机视图下放在手机框右侧，桌面视图下做成可收起的抽屉。

**主题**：两套颜色都定义为 CSS 变量。深色沿用旧 DESIGN.md 色板：背景 #101722、表面 #17212e、边线 #34465b、正文 #edf1f6、次要文字 #b3bfd0、金色主操作 #dab873。浅色用白底加企微蓝系结构，金色只做品牌点缀，取加深值保证对比度。状态色两套各自校准。

**固定日期**：原型里的"今天"固定为 2026-10-12，虚拟数据不会随时间过期。

## 4. 模块与页面（13 个模块 + 企微形态，约 64 页）

列表页在手机视图下自动转为卡片，所以同一页面两种视图共用。

1. **工作台**（1 页）：按岗位显示我的交接（待接收／待处理）、待办、待我审批、我发起的审批、本岗位 3–4 个关键数。
2. **客户与跟进**（8 页）
   - 客户列表
   - 客户详情：档案、自定义字段、跟进、消费记录、业务单、企微绑定
   - 预约与跟进
   - 公海与再分配：规则 + 日志
   - 活码获客：门店柜台码、小程序码、活动码，带来源标签
   - 话术与素材
   - 登记表与字段
   - 顾问工作统计
3. **业务单**（3 页）
   - 列表：可切换为 6 阶段看板
   - 详情：6 阶段进度、当前主责、记录链时间线、报价版本对比、付款／生产／交付三个独立状态、成本与毛利、关联审批与交接
   - 售后与取消
4. **商品与设计**（3 页）：系列款式；款式详情（设计版本、标准组成、目标成本）；设计变更。
5. **采购与库存**（9 页）
   - 供应商、采购单、原料批次
   - 批次详情：数量平衡
   - 成品库存：材料／纯度／批次／库位／条码多级查询
   - 成品详情：编号、金净重、总重、库位、锁定、实际用料
   - 库存流水：领退料、调拨、盘点三个页签
   - 仓库工作台大屏
   - 单据与标签打印设置
6. **生产与质检**（5 页）：排产看板；产能与工序；生产任务；任务详情（用料、实际工费、质检、返工）；质检记录。
7. **财务**（5 页）
   - 收退款核对
   - 成本与毛利
   - 定金与预存款 ※
   - 往来对账：客户、供应商、账期欠款三个页签 ※
   - 收款流水导入 ※
8. **会计税务**（4 页）：凭证列表、凭证详情、发票、税务概览 ※
9. **人事与提成**（4 页）：员工、考勤、提成与计件、工资单
10. **经营看板**（6 页）：总览、批次总盘、系列与订单总盘、门店对比、异常下钻、报表中心（销售／仓库／财务／生产）
11. **小程序后台**（4 页）
    - 实时数据：访客、预约、订单、支付指标，加滚动的事件流。事件流按计时器逐条显示预置事件，只在演示里出现，不写入数据；点任一事件跳到对应客户或业务单。
    - 订单链路：小程序订单 → 客户 → 业务单 → 生产或交付 → 收款
    - 同步记录：成功、失败重试、重复推送被识别
    - 活动与内容：旧营销中心并到这里
12. **审批中心**（3 页）：审批列表、审批详情（审批链、原业务单）、审批规则
13. **系统设置**（6 页）：岗位权限矩阵、账号、企微配置、小程序配置、设备绑定（电子秤、扫码枪、标签打印机）、操作日志
14. **企微形态**（3 页）
    - 聊天侧边栏：左边是模拟聊天窗口，右边显示客户档案、进行中业务单、报价版本、话术、素材、快捷跟进
    - 消息通知：企微应用消息卡片，点开直达对应记录
    - 客户联系：外部联系人与客户编号的绑定、来源活码、跟进顾问、离职继承示例

※ 页面顶部标"待商家核实"：是否有批发或赊账、定金规则、税务口径都未知。所有税额标"模拟口径，未经会计核实"，不写任何真实税率或政策。

旧功能的处理：行情中心降为"参考金价＋来源＋时点"卡片，出现在报价和看板里；AI 助理去掉。

| 组 | 岗位 | 工作台重点 | 可见模块 |
|---|---|---|---|
| 管理层 | 老板 | 超总经理额度的审批、经营摘要、重大异常 | 除系统设置外全部可看；看板、审批为主 |
| | 总经理 | 待我审批、跨部门延期与异常、交接总览 | 除系统设置外全部可看；审批为主 |

## 6. 业务单主线（对应图稿 01）

- 6 阶段：需求登记 → 方案报价 → 确认立单 → 备货与生产 → 质检与交付 → 售后与复盘。
- 4 条泳道：产品与成本、销售与利润、供应链与商品、财务与资金。
- 详情页的记录链依次是：需求 → 报价版本 → 客户确认凭据 → 设计版本 → 现货锁定或生产任务 → 实际用料与批次 → 质检（含返工、复检）→ 成品 → 交付 → 收退款 → 售后。每一环都显示经办人、时间，并能点进原记录。
- 口径（从旧 demo 审查继承）：
  - 报价＝参考金价×计价克重＋对客工费＋配件，每个版本保留价源和时点。
  - 实际成本只计实际发生的部分。毛利＝成交价－已确认成本，未确认的费用显示"待补"，不计入。
  - 称重差异单列为"待核对"，不直接算作损耗。
  - 返工追加费用，首轮用料保留。
  - 确认之后改价，状态退回"待确认"。

## 7. 虚拟数据剧本

- 主体：示例金店（虚构）。城东店、城西店、小程序商城，一个自有工厂。约 22 名员工覆盖 16 个岗位，其中两店各有店长 1 名、顾问 2 名。
- 主线：导图 07 的 100g 批次。批次 PC-001 共 100g，A 为纯金系列，B 系列含 B1–B4 四个款式。结清结果是 90g 成品净含金、5g 余料在库、3g 回收料、2g 确认损耗。第二个批次 PC-002 处于在制状态，带一条 0.3g 的待核对差异，用来演示未结清的情况。
- 规模：约 20 个客户、12 张业务单覆盖全部 6 个阶段，以下情形每种至少一条：
  - 现货锁定出库
  - 定制先收定金
  - 返工后复检
  - 退货退款，金额超过 1000 元，上转总经理
  - 取消单，保留已发生费用
  - 价格例外，等待总经理审批
  - 小程序订单，其中一次同步失败后重试成功
  - 跨店调拨
  - 账期大客户（※）
- 计量单位：金额用整数"分"，重量用整数"毫克"。编号是静态可读的，如 KH-001、YW-2026-001、PC-001、CP-001、RW-001、SK-001、PZ-001、SP-001，并由检查脚本保证不重复。
- 下列数字不手写，一律由基础记录经纯函数推算，保证前后对得上：
  - 看板、门店对比、报表的各项合计
  - 毛利
  - 批次平衡：原量＝成品净含金＋余料＋回收料＋确认损耗＋在制＋待核对
  - 顾问提成：已收款订单 × 虚拟比例
  - 工厂计件：已完成任务 × 虚拟单价
  - 凭证：由收款、采购、退款、工资推出

## 8. 技术方案

- 新建 `app/`，使用 React 18、TypeScript、Vite。旧 `demo/` 原样保留。
- 不引组件库和路由库：用纯 CSS 加 CSS 变量；用一个约 30 行的 hash 路由，配一张路由表，表里每条记录包含路径、页面、所属模块、说明文字。
- 目录：
  - `src/shell/`：控制栏、手机框、桌面框、导航、说明面板
  - `src/ui/`：通用列表（表格在手机上转卡片）、详情分区、指标卡、时间线、阶段条、状态标签
  - `src/pages/<模块>/`：各模块页面
  - `src/data/`：静态数据和推算函数
  - `src/roles.ts`：岗位、可见范围、工作台配置
- 页面尽量写成"列配置＋数据"，直接复用通用组件，减少重复代码，也方便以后用技能统一改样式。

## 9. 验收

1. 逐个切换 16 个岗位：工作台内容和导航入口与第 5 节一致，不可见的模块不出现。
2. 每页在手机和桌面两种视图下都能正常显示；手机视图没有横向滚动，表格转为卡片。
3. 四种企微形态都能打开：消息卡片能直达对应记录；侧边栏显示的是当前客户自己的业务单；非面向客户的岗位看到相应提示。
4. 主线能走通：从小程序订单或消息进入业务单，再到成品、实际用料、批次 PC-001，批次页显示 100g＝90＋5＋3＋2；从看板异常能下钻回原记录。
5. 深、浅两套主题在每页都能切换，文字可读。
6. `npm run build` 通过。`npm run check` 通过，检查：数据引用的编号都存在且不重复；批次平衡成立；页面里所有内部链接都能对上路由表。
7. 浏览器里逐个模块、两种视图点一遍，控制台没有报错。
8. 标 ※ 的页面和阈值都带"待商家核实"或"虚拟"标记。

## 10. 不做

- 修改数据，或保存业务数据
- 真实的企微、小程序、支付、行情、银行接口
- 登录与真实权限
- 服务器
- 真实税率与税务政策
- AI 助理
- 检查脚本以外的测试
- 多语言

实施时按批次推进：先做外壳、数据和通用组件，再按模块组逐批完成，每批都要验收。这样单次任务不会超出 token 预算。
